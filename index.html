List & Menu Actions — Functional Use Cases

This is a problem-oriented guide to the Actions app features that are most useful when a Shortcut needs to build, inspect, filter, transform, or present a list/menu. Search the catalog below for the bold action names or the quoted search terms.

Building a menu from changing data

Create Menu / menu-related Actions are useful when the choices should be generated at runtime instead of being permanently typed into Shortcuts' built-in Choose from Menu. Typical sources are Data Jar keys, files in a folder, JSON records, device names, project names, tags, or results returned earlier in the Shortcut.

Use it when: the number, names, or order of choices can change. For a fixed handful of choices, Apple's built-in Choose from Menu is usually simpler.

Presenting a list for the user to choose from

Look for Choose from List, Choose from List (Extended), and related list-selection Actions. These are useful for turning raw data into an interactive selector, especially where you want richer labels, multiple selection, or behavior beyond the stock Shortcuts picker.

Examples: choose one Data Jar child key; pick several files for batch processing; select a vehicle/project from JSON; choose one of the results returned by a search.

Filtering a list before presenting it

Search for list filtering/matching Actions. Use these when you have the full collection already but only want entries meeting a condition.

Examples: only keys beginning with shop.; only filenames ending in .json; only records whose status is open; remove blank entries before displaying a menu.

Finding one item or its position

Search the catalog for index, find, contains, and list. These Actions answer questions such as “does this item exist?”, “which item matched?”, and “where in the list is it?”

Useful pattern: maintain a master list, find the selected item's index, then use that index to retrieve a corresponding value from a second parallel list.

Getting, removing, or replacing items

Search for Get Item, Remove, Replace, and List. These are useful when treating a list as a small data structure rather than just something to display.

Examples: pop the first queued job; remove a completed task; replace an outdated entry; retrieve the nth element supplied by another calculation.

Sorting and de-duplicating

Search for Sort, Unique, Duplicate, and List. These are especially useful before presenting dynamically collected information to a user.

Examples: alphabetize Data Jar keys; collapse repeated tags; sort numbers numerically instead of alphabetically; turn messy collected input into a clean menu.

Chunking / grouping a long list

Search for chunk, group, or list. These help divide a large collection into manageable batches.

Examples: process 100 records ten at a time; split a long menu into categories; batch API/file operations; paginate results.

Randomizing or selecting random entries

Search for random and list. Useful for sampling, rotating choices, test data, or selecting an item without maintaining your own random-index logic.

Converting between text and lists

Many Shortcuts workflows cross the boundary between newline-delimited text and actual List values. Search for split, join, lines, and list.

Examples: turn pasted lines into selectable entries; join selected items for a notification; convert exported keys into one-item-per-line text; parse a simple text file into menu choices.

Menus as routers

A menu does not have to contain the work itself. A useful pattern is selection → identifier → downstream Shortcut/action. Keep the menu as the front-end router and let separate Shortcuts perform the jobs.

Example: a shop utility menu can return weld_card, databoss, or wire_lookup; a later action uses that returned identifier to route execution. This keeps the visible labels friendly while the internal values stay stable.

Lists as lightweight lookup tables

Two synchronized lists can behave like a primitive key/value table: one list contains display names and the other contains values. Find the chosen display item's index, then retrieve the value at the same index. For anything that grows beyond a small set, a Dictionary/JSON object is generally safer.

When to use Dictionary/JSON instead

Use a List when each element is basically “one thing.” Use a Dictionary/JSON object when each item has several properties such as name, id, location, and status. You can still extract the names into a list for the menu, then use the selection to retrieve the complete record.
